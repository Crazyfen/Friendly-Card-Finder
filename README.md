# FriendlyCardFinder

FriendlyCardFinder — бот для Telegram и Discord, который ищет карточки Magic: The Gathering по спискам пользователей Deckbox.org. Бот парсит профили Deckbox, сохраняет инвентари/трейдлисты/вишлисты в SQLite и отвечает на запросы поиска карточек в зарегистрированных списках. Для оператора есть веб-панель администратора с управлением пользователями и аналитикой.

**Ключевые возможности**

- Две платформы из одного процесса и одной базы: Telegram и Discord (Discord включается токеном и необязателен)
- Регистрация пользователя Telegram или Discord с привязкой к логину Deckbox
- Асинхронная загрузка и периодическое обновление списков (inventory, tradelist, wishlist)
- Поиск карточек по именам с поддержкой больших коллекций (батчевые вставки в SQLite) и поиск в вишлистах через команду `/sell` — поддерживаются многострочные запросы (по одной карточке на строку)
- В результатах поиска — контакты владельца на обеих платформах: сначала на платформе читателя, затем на другой
- Веб-панель администратора: удаление и отвязка пользователей, ручное обновление, аналитика спроса
- Поддержка FTS5 (если сборка SQLite с FTS5)

**Команды в Telegram**

| Команда                   | Что делает                                                                        |
| ------------------------- | --------------------------------------------------------------------------------- |
| `/start`                  | Приветствие и краткая справка                                                     |
| `/deckbox <login>`        | Регистрация: привязывает Telegram-пользователя к логину Deckbox и загружает списки |
| `/suggestdeckbox`         | Пакетное обновление списков; логины перечисляются по одному на строку              |
| `/sell <название>`        | Поиск по вишлистам; многострочный ввод, по одной карточке на строку                |
| *(любой текст)*           | Поиск карточки по имени в трейдлистах зарегистрированных пользователей             |

**Команды в Discord**

| Команда                   | Что делает                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------- |
| `/help`                   | Приветствие и краткая справка (видно только вам)                                                  |
| `/deckbox login:<login>`  | Регистрация: привязывает Discord-аккаунт к логину Deckbox (ответ видно только вам)                |
| `/search card:<название>` | Поиск по трейдлистам. Без аргумента открывает форму, куда можно вставить список, по карточке на строку |
| `/sell card:<название>`   | Поиск по вишлистам; без аргумента — та же форма                                                    |
| `/suggestdeckbox`         | Открывает форму для логинов (по одному на строку); итог придёт сообщением в канал с упоминанием вас |
| ЛС боту или `@бот <текст>` | Поиск по трейдлистам, как обычное сообщение в Telegram (ответ всегда на английском)                |

Аргумент слэш-команды — всегда одна карточка целиком: у многих карт в названии есть запятые (*Kozilek, Butcher of Truth*), поэтому несколько карт вводятся через форму, по одной на строку. Бот не читает обычные сообщения в каналах (privileged-интент Message Content не используется) — только слэш-команды, личные сообщения и сообщения с упоминанием бота. Ответы никого не пингуют, кроме итога `/suggestdeckbox`, который упоминает только того, кто его запустил.

Поиск по точному совпадению (обе платформы): заключите имя в кавычки — `"Shock"`. Поддерживаются пары `""`, `''`, `«»`, `“”`, `‘’`, `„“`, `„”`. Без кавычек выполняется поиск по префиксу, нечувствительный к регистру и диакритике.

**Регистрация на двух платформах**

Один логин Deckbox может быть привязан к одному аккаунту Telegram и одному аккаунту Discord — это две независимые регистрации, они не связываются между собой. Владелец, зарегистрированный на обеих платформах, показывается в результатах с обоими контактами.

**Веб-панель администратора**

Панель работает внутри процесса бота на `ADMIN_ADDR` (по умолчанию `:8081`) и наружу порт не публикует: TLS и сертификат Let's Encrypt обеспечивает сайдкар Caddy, который проксирует на панель домен `ADMIN_DOMAIN` (по умолчанию `admin.ivash.net`). Вход — HTTP Basic Auth (`ADMIN_USER`/`ADMIN_PASSWORD`); без `ADMIN_PASSWORD` панель не запускается.

- `/` — управление: пользователи Deckbox с их контактами в Telegram и Discord, добавление логина, ручное обновление списков, **Purge** (удалить пользователя Deckbox, его списки и все регистрации на него) и **Unlink** (отвязать один аккаунт Telegram или Discord, сохранив коллекцию), список «осиротевших» регистраций (логин, по которому так и не загрузилась коллекция — обычно опечатка)
- `/insights` — аналитика: поиски по дням, спрос без предложения, самые разыскиваемые карты, пары для обмена, концентрация предложения (кэшируется на 5 минут)

**Текущая структура проекта (важные пути)**

- `main.go` — точка входа: конфиг, хранилище, scraper, фоновое обновление, панель; запускает адаптеры Telegram и Discord
- `internal/deckbox/` — доменная логика Deckbox (scraper, `Deckbox`-ресивер, модели); не знает ни про платформы, ни про переводы
- `internal/chat/` — поведение всех команд, общее для обеих платформ; результаты поиска рендерятся в платформенно-нейтральные `message.Message`
- `internal/message/` — сообщение как набор фрагментов (текст, жирный, код, ссылка, контакты)
- `internal/telegram/` — адаптер Telegram и форматирование в Telegram HTML
- `internal/discord/` — адаптер Discord (слэш-команды, формы, ЛС, упоминания) и форматирование в Discord Markdown
- `internal/i18n/` — переводы RU/EN без разметки
- `internal/admin/` — веб-панель администратора (`net/http` + встроенные `html/template`)
- `internal/storage/sqlite/` — реализация хранения в SQLite (батчинг, FTS, миграции goose)

**Требования**

- Go 1.26+ (версия из `go.mod` — на текущий момент `go 1.26.8`)
- SQLite (драйвер используется `github.com/mattn/go-sqlite3`, нужен CGO)

**Переменные окружения (.env)**
Обязательно установить в окружении или в файле `.env` в корне проекта:

- `BOT_TOKEN` — токен Telegram-бота
- `STORAGE_PATH` — путь к файлу SQLite базы (например `./data/db.sqlite`)
- `DECKBOX_LOGIN` + `DECKBOX_PASSWORD` — учётные данные Deckbox; бот сам логинится и получает session cookie (сохраняется в `<папка storage>/deckbox_session` и переиспользуется между перезапусками)
- `ENV` — `local`/`dev`/`prod` (влияет на уровень логирования)

Для доступа к Deckbox нужно задать **либо** `DECKBOX_LOGIN`+`DECKBOX_PASSWORD`, **либо** `DECKBOX_SESSION_COOKIE` (см. ниже).

Дополнительные опции (необязательно):

- `DISCORD_TOKEN` — токен Discord-бота; пустое значение отключает Discord
- `ADMIN_PASSWORD` — пароль веб-панели; пустое значение отключает панель
- `ADMIN_USER` — логин веб-панели (по умолчанию `admin`)
- `ADMIN_ADDR` — адрес, который панель слушает внутри контейнера (по умолчанию `:8081`)
- `ADMIN_DOMAIN` — публичный домен панели; читает Caddyfile, а не бот (по умолчанию `admin.ivash.net`)
- `DECKBOX_SESSION_COOKIE` — ручной override значения `_tcg_session`; если задан, используется напрямую без логина
- `FRESHNESS_TIME_LIMIT_HOURS` — время, после которого `/suggestdeckbox` считает данные "устаревшими" (по умолчанию 24)
- `CARD_LIST_REFRESH_HOURS` — время, после которого списки автоматически обновляются в фоне (по умолчанию 3)
- `CARD_LIST_BATCH_SIZE` — размер батча при вставке карточек в БД (по умолчанию 1000)

Пример `.env`:

```
BOT_TOKEN=123456:ABCDEFG
STORAGE_PATH=./data/db.sqlite
DECKBOX_LOGIN=your_email@example.com
DECKBOX_PASSWORD=your_password
ENV=local
DISCORD_TOKEN=your_discord_bot_token
ADMIN_PASSWORD=a_long_random_password
```

**Настройка Discord-бота**

1. Создайте приложение в [Discord Developer Portal](https://discord.com/developers/applications), во вкладке **Bot** скопируйте токен в `DISCORD_TOKEN`. Privileged-интенты (в том числе Message Content) включать не нужно.
2. Во вкладке **OAuth2 → URL Generator** выберите scopes `bot` и `applications.commands`, права — Send Messages и Read Message History, и пригласите бота на сервер по полученной ссылке.
3. При запуске бот сам регистрирует глобальные слэш-команды; в первый раз они могут появиться в клиенте Discord с задержкой.

**Сборка и запуск**

Сборка обычным способом:

```bash
go build ./...
./FriendlyCardFinder
```

Запуск без сборки (go run):

```bash
go run main.go
```

Если требуется поддержка FTS5 (для ускоренного поиска), соберите с тегом `fts5`:

```bash
# сборка с FTS5
go build -tags "fts5" ./...
go run -tags "fts5" main.go
```

**Тесты**

Запустить все тесты:

```bash
go test ./...
```

FTS-тесты (требуют сборки драйвера с поддержкой FTS5):

```bash
go test -tags "fts5" ./internal/storage/sqlite -v
```

Интеграционные тесты, которые взаимодействуют с Deckbox, требуют авторизации (`DECKBOX_LOGIN`+`DECKBOX_PASSWORD` или override `DECKBOX_SESSION_COOKIE`) в окружении и доступа в сеть; иначе они пропускаются. Адаптеры Telegram и Discord, команды и панель тестируются без сети, токенов и настоящей базы.

**Особенности реализации и советы для разработчиков**

- Хранение: используется отдельное подключение для записи (один поток) и отдельное для чтения (параллельно). В инициализации применяются PRAGMA: `WAL`, `synchronous = NORMAL`, `busy_timeout = 5000`.
- Батчинг: вставки карточек разбиваются на батчи (~1000 карточек) чтобы не превышать лимит параметров SQLite.
- FTS5: при наличии поддержки создаётся виртуальная таблица `card_lists_fts` и поддерживаются нормализованные токены для поиска без диакритики.
- Разметка: переводы и команды не содержат разметки; каждая платформа форматирует `message.Message` сама (HTML для Telegram, Markdown для Discord) и экранирует весь текст, так что спецсимволы в названиях карт и логинах (`_`, `*`, `<`, `&`) отображаются как есть.
- Discord: поиск и `/deckbox` сначала отвечают «думаю…», а результат присылают следом — чтобы уложиться в трёхсекундное окно ответа Discord.

**Разработка новых команд**

- Добавьте метод на `chat.Commands` в `internal/chat/command.go`, а бизнес-логику — методом на `Deckbox` в `internal/deckbox/handler.go`. Метод `Deckbox` возвращает значения, а не готовый текст: формулировки живут в `internal/i18n` и `internal/chat`.
- Зарегистрируйте команду в обоих адаптерах: в `internal/telegram/telegram.go` и в `applicationCommands()` и `onInteraction` в `internal/discord/discord.go`.
- Команды тестируются против фейкового `chat.Domain`, без бота, базы и scraper. Для асинхронных потоков соберите `Deckbox` через `New` с моками `DeckboxSaver`, `AdminStore` и `Fetcher`.

Подробные соглашения по коду (логирование, обработка ошибок, батчинг, FTS5, worker pools) — в [`CLAUDE.md`](CLAUDE.md).

**Запуск через Docker**

Собрать образ локально:

```bash
docker build -t friendlycardfinder .
```

Запустить с `docker compose` (требует `.env` в текущей директории):

```bash
docker compose up -d
```

Compose поднимает два сервиса: `bot` (без опубликованных портов) и `caddy` (порты 80/443, TLS для веб-панели). Чтобы Caddy получил сертификат, DNS-запись `ADMIN_DOMAIN` должна указывать на сервер.

**CI/CD (GitHub Actions)**

При каждом пуше в ветку `main` автоматически выполняются:

1. `go test -tags fts5 -race ./...`
2. Сборка Docker-образа и публикация в GitHub Container Registry (`ghcr.io/crazyfen/friendlycardfinder`)
3. Деплой на VPS: копирование `docker-compose.yml` и `Caddyfile` по SCP, затем `docker compose pull && up -d`

Необходимые GitHub Secrets:

| Secret            | Описание                                     |
| ----------------- | -------------------------------------------- |
| `SSH_HOST`        | IP или домен VPS                             |
| `SSH_USER`        | Пользователь SSH                             |
| `SSH_PRIVATE_KEY` | Приватный SSH-ключ (полное содержимое файла) |

`.env` на VPS с `BOT_TOKEN`, `STORAGE_PATH`, `DECKBOX_LOGIN`, `DECKBOX_PASSWORD`, `ENV` (и при необходимости `DISCORD_TOKEN`, `ADMIN_PASSWORD`) необходимо создать вручную один раз в директории `~/friendlycardfinder/`.
